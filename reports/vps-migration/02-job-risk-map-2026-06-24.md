# Этап 2 — Job risk map (двойной запуск Railway + VPS)

**Дата:** 2026-06-24  
**Цель:** классифицировать риск одновременного запуска каждого сервиса на Railway и VPS.

## Правило миграции jobs

```
1. Выключить job на Railway
2. Включить job на VPS
3. Проверить один run
4. Проверить DB writes / логи
5. Отчёт
6. Только потом следующий job
```

**До DNS cutover:** на VPS разрешён только **сайт** (read path + webhooks при отсутствии трафика на VPS).

---

## Матрица рисков

| Сервис | Риск | DB writes | Email | GSC quota | Lock / idempotency | Одновременно с Railway |
|--------|------|-----------|-------|-----------|-------------------|------------------------|
| Сайт | **низкий** | да (API) | transactional | косвенно | HTTP stateless | да до cutover* |
| Скрипты | **высокий** | **да** | нет | нет | слабая | **НЕТ** |
| Сео генерация | **высокий** | **да** | нет | нет | queue-based | **НЕТ** |
| Сео индексация | **высокий** | **да** | нет | **да** | queue + daily cap | **НЕТ** |
| Сео Аудит | **низкий/средний** | нет | нет | read-only | нет | осторожно** |
| Рассылка | **высокий** | да | **да** | нет | cooldown | **НЕТ** |
| Рассылка провайдеры | **высокий** | да | **да** | нет | partial | **НЕТ** (сейчас RUNNING) |
| Контент Хаб | **высокий** | **да** | нет | нет | topic attempts | **НЕТ** |
| Перевод | **высокий** | **да** | нет | нет | DB lock | **НЕТ** |

\*Сайт на VPS без DNS — только smoke на IP/временном домене; production трафик остаётся на Railway.  
\*\*Seo Аудит — read-only, но дублирует Telegram-алерты если `JSONLD_AUDIT_BASE_URL` указывает на тот же origin.

## Детали по сервисам

### 1. Сайт — низкий риск

**Почему низкий:** stateless HTTP; основной риск — двойной приём webhook/payment при двух публичных URL.

**Что проверять на VPS smoke:**
- Supabase read (anon + server)
- sitemap / canonical / robots
- нет 500 на ключевых URL

**Можно параллельно:** да (staging origin без production DNS).

**Стоп-факторы:** sitemap 404/500, canonical drift, Supabase connection error.

---

### 2. Скрипты — высокий риск

**Start:** `bash scripts/railway-cron.sh all` каждые 2 часа.

**Опасные subtasks:**
| Task | Script | Writes |
|------|--------|--------|
| enrich-providers | `scripts/enrich-all-providers.ts` | providers table |
| essay-pipeline | `scripts/run-essay-pipeline-full.ts` | essays, storage |
| manual-essay-guides | enqueue + run + audit | essay guides queue |

**Почему высокий:** нет глобального lock; повторный cron = duplicate AI spend + inconsistent DB.

**Можно параллельно:** **НЕТ**

---

### 3. Сео генерация — высокий риск

**Start:** `bash scripts/railway-cron.sh seo-generation-http` каждые 3 часа.

**Flow:** HTTP POST к live site `/api/internal/seo/*` с `GOOGLE_INDEXING_SECRET`.

**Почему высокий:**
- Генерирует SEO pages + meta в Supabase
- Два воркера → duplicate pages / meta overwrite race

**Можно параллельно:** **НЕТ**

**Порядок переноса (после сайта):** #2 в очереди jobs (после Seo Аудит).

---

### 4. Сео индексация — высокий риск

**Start:** flush + url-inspection каждые 4 часа.

**Почему высокий:**
- Google Indexing API daily quota (`GOOGLE_INDEXING_MAX_PUBLISH_PER_DAY`)
- URL Inspection API quota
- `public.google_indexing_queue` — duplicate publish attempts

**Можно параллельно:** **НЕТ**

**Порядок переноса:** #8 (последний среди jobs) — самый чувствительный к quota.

---

### 5. Сео Аудит — низкий/средний риск

**Start:** `npm run audit:jsonld-sitemap:prod` daily 09:00 UTC.

**Почему низкий:** только HTTP fetch + parse; DB не пишет.

**Почему средний:** Telegram notify при failures; два аудита = duplicate alerts.

**Можно параллельно:** да, если VPS audit смотрит на staging URL (`JSONLD_AUDIT_BASE_URL`).

**Порядок переноса:** #1 (первый job после стабильного сайта).

---

### 6. Рассылка — высокий риск

**Start:** `grant-notifications` daily 00:30 UTC.

**Почему высокий:**
- Resend emails пользователям
- Cooldown есть, но resend-all флаги опасны
- Duplicate run = duplicate digest emails

**Можно параллельно:** **НЕТ**

---

### 7. Рассылка провайдеры — высокий риск

**Статус сейчас:** **RUNNING** на Railway (outreach + `tail -f /dev/null`).

**Почему высокий:**
- Cold outreach emails via Resend
- DB tracking outreach state

**Можно параллельно:** **НЕТ** — дождаться завершения текущего Railway run или остановить сервис перед VPS.

---

### 8. Контент Хаб — высокий риск

**Root:** `services/content-hub`  
**Start:** `npm run content:run-once` (one-shot)

**Почему высокий:**
- Publishes `content_posts`
- OpenAI + optional FAL
- Callback to site `CONTENT_ARTICLE_MATCH_SECRET`

**Можно параллельно:** **НЕТ**

---

### 9. Перевод — высокий риск

**Start:** `npm run i18n:scholarship-autopilot:railway`

**Защита:** DB lock `i18n_scholarship_autopilot_is_locked()` + `I18N_WORKER_REQUIRE_LOCK`.

**Почему всё равно высокий:**
- Lock не защищает от двух разных environments, если оба с `I18N_PILOT_ALLOW_PRODUCTION=1`
- Wave resume state в DB — race на `I18N_WORKER_START_WAVE`

**Можно параллельно:** **НЕТ**

## Главные стоп-факторы (остановить миграцию)

| Симптом | Вероятная причина |
|---------|-------------------|
| sitemap пустой / 404 / 500 | site misconfig |
| scholarship sitemap shard broken | build/cache issue |
| canonical изменился | env URL mismatch |
| index/noindex изменился | SEO regression |
| Supabase connection error | env keys / network |
| duplicate DB rows | job запущен дважды |
| повторная рассылка | mailing на Railway + VPS |
| indexing quota spike | seo-indexing duplicate |

## VPS этап 3 — что включать

```
site          → ON
all jobs      → OFF (cron disabled, workers not started)
env/          → chmod 600
logs/         → writable
backups/      → empty, ready
```

Docker Compose profile suggestion:

```yaml
# profiles: ["site"] only on stage 3
# profiles: ["jobs"] — DO NOT enable until per-job migration
```
